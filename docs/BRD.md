## 1. 业务摘要

本项目面向 UW–Madison 正在寻找科研经历的学生。学生可以只描述一个模糊兴趣，也可以补充专业、年级或简历；系统帮助他们探索研究方向、理解教授和实验室的工作、比较候选对象，并通过正确的渠道采取下一步行动。

产品由介绍首页和独立工具页面组成。访问者在首页理解用途，点击 **Get Started** 后进入探索流程。主要路径为：

**介绍首页 → 表达兴趣 → 探索方向／查看教授 → 看懂研究 → 比较和选择 → 准备申请或联系材料 → 邮箱授权与批量发送 → 保存联系记录。**

核心价值是让没有科研经验的学生也能形成有依据的选择。推荐、解释、比较和联系共同构成完整体验；邮件生成与批量发送是必要的行动能力，但不是衡量产品价值的唯一方式。

## 2. 背景与需求依据

### 2.1 比赛背景

目标挑战为 DoIT Academic Technology 的 **Badgers Building for Badgers**。用户提供的赛事截图要求通过技术改善 UW 学生的学习、工作或校园生活，并提及优秀项目可能有机会继续与 DoIT 开发。本项目聚焦校内学术探索和本科科研参与，主题相关性明确。

这不代表项目已经得到学校背书、获得系统接入权或形成 DoIT 合作。赛事文字依据用户提供的截图；比赛网页在本次核查中无法读取，未据此推断其他评审规则。[S1]

### 2.2 已有证据与证据边界

| 依据 | 可以支持的判断 | 不能据此得出的结论 |
|---|---|---|
| 用户与团队的讨论 | 团队认同首次找科研、理解研究和选择联系对象是值得解决的问题 | 不能替代更广泛的学生需求验证 |
| WISCIENCE 官方找导师指南 | 学生需要探索兴趣、查阅研究介绍、选择导师并联系；校方已有相应指导资源 [S2] | 不能证明所有学生都需要新的软件，也不能推算市场规模 |
| FindMyProf 的公开项目说明 | 简历分析、教授匹配和邮件草拟已有相似实现 [S3] | 没有完整测试，不能断言竞争产品一定缺乏某项能力 |
| 用户提供的视频观察与截图 | 可参考“介绍首页 → Get Started → 工具”的组织方式 | 不以截图作为后台功能、推荐质量或实际发信能力的证明 |
| 本次邮箱文档核查 | 学校使用 Microsoft 365；授权后存在发信接口 [S4–S6] | 尚未证明本项目应用可直接获得 UW 账户授权 |

仓库中前两轮研究保留了其他方向的探索过程。住房、提交核验和楼内导航等先前候选不是当前产品范围，不能作为本方案的已确认需求。

### 2.3 需要解决的问题

1. 学生只知道“对 AI／生物／心理学感兴趣”，不知道怎样进一步理解研究方向。
2. 教授和实验室信息分散；专业介绍和论文标题对初学者不易理解。
3. 看过多个网页后，学生仍难以说明候选实验室之间的区别，以及自己为什么选择其中一个。
4. 公开网页对本科生参与、学分、薪酬和招募状态的说明并不完整。
5. 联系方式不统一：有的需要邮件，有的要求填写表单或通过项目申请。
6. 学生希望高效联系多个对象，同时对重点对象补充真实、具体的内容。

### 2.4 产品不承诺解决的问题

产品不能创造实验室名额，不能判断教授实际带教容量，不能保证录取、回复或带薪机会，也不能把网页没有写出的条件推断为确定事实。学生没有科研经历，不应成为工具拒绝推荐的原因。

## 3. 目标用户与使用情境

### 3.1 主要用户

UW–Madison 本科生，尤其是第一次寻找科研经历、尚不熟悉研究方向或申请渠道的学生。不限年级、专业或既有科研经验；“第一次科研”是设计重点，不是排除其他本科生的资格条件。

常见使用情境：

| 情境 | 用户起点 | 用户希望获得的结果 |
|---|---|---|
| 兴趣模糊 | “我对 AI 感兴趣” | 看懂几类研究问题，并找到值得了解的教授 |
| 方向明确 | “想研究 agent 的规划与工具使用” | 直接得到相关教授、实验室和公开依据 |
| 多个兴趣 | “agent 和 AI 教育应用都想看看” | 分组探索、比较交叉关系，不被强制限定为交集 |
| 有简历但想转方向 | 过去做网页开发，现在想探索机器人 | 兴趣优先，简历辅助理解，不把过去经历当作未来限制 |
| 已有候选 | 已知道一位教授或实验室 | 直接搜索、看懂研究、核对参与方式并准备联系 |

### 3.2 相关方

| 相关方 | 预期收益或关注点 | 第一版参与方式 |
|---|---|---|
| 学生 | 降低探索门槛，理解研究，形成候选名单和下一步 | 直接使用 |
| 教授、实验室 | 学生联系时更了解研究，并遵循公开申请渠道 | 不是第一版必须入驻的用户 |
| 学校指导人员／DoIT | 对学生有实际帮助、说明可信、体验可用 | 可作为后续反馈或合作对象；尚未联系或确认 |
| 项目团队 | 可完成、可展示、可验证的产品 | 负责内容核查、设计、实现与用户验证 |
| 邮箱与 AI 服务提供方 | 身份授权、接口可用性和服务约束 | 必须验证的外部依赖 |

## 4. 价值主张与差异化

### 4.1 对用户的承诺

**从你已有的一点兴趣开始，帮助你看懂 UW 的研究、比较值得了解的导师，并知道怎样迈出下一步。**

### 4.2 与现有替代方式的关系

| 替代方式 | 已有优势 | 本产品需要证明的增量价值 |
|---|---|---|
| 直接浏览教授主页 | 一手信息、原始联系方式 | 减少逐页理解与整理成本，提供通俗说明和统一比较 |
| 社交媒体、同学推荐 | 个人经验、关系和非公开线索 | 提供可追溯的公开资料与完整操作流程；不替代人际建议 |
| 通用联网 AI | 可搜索、总结、比较和撰写邮件 | 无需反复设计提示词，固定处理未知信息，保留选择和联系进度 |
| 教授检索与群发邮件工具 | 联系效率高、操作集中 | 加强研究理解、兴趣探索、选择依据与正确申请路径 |
| 学校指南和指导活动 | 专业指导、校内经验 | 帮助学生把指导中的步骤应用到自己的具体搜索 |

不能以“通用 AI 做不到”作为卖点。当前差异主要来自完整流程、信息组织、依据可追溯和面向初学者的解释质量。是否构成显著优势，需要与通用联网 AI 和手动检索进行同条件比较。

### 4.3 核心产品特色

1. **适应兴趣清晰程度。** 模糊兴趣先展示容易理解的方向；明确兴趣直接展示对象；多个兴趣允许并列探索。
2. **帮助学生读懂研究。** 说明研究问题、实际例子、常见方法和代表材料，使学生能解释自己为什么感兴趣。
3. **公开事实与未知信息分开。** 支持／不支持／未说明的条件标签可追溯；明确暂无空缺的对象不作为立即申请的默认推荐。
4. **比较后再行动。** 选择邮件、表单或项目申请等适当入口；对选定对象快速批量生成，也可通过短问题加入真实内容。
5. **集中处理发送。** 学生连接自己的邮箱，在统一预览中选择邮件并批量发送，每位教授收到独立内容。

更多字段、更多教授和更长的解释本身不构成差异化。优先让学生理解和作出选择。

## 5. 业务目标与范围

### 5.1 业务目标

| 编号 | 目标 | 预期用户结果 |
|---|---|---|
| BG-01 | 降低开始门槛 | 一句话即可开始，不强制填写长表或上传简历 |
| BG-02 | 增强研究理解 | 能用自己的话说明候选实验室研究什么 |
| BG-03 | 支持自主选择 | 能比较至少两个候选并给出个人选择理由 |
| BG-04 | 减少错误行动 | 找到正确的公开申请入口，不把未知条件当作确定事实 |
| BG-05 | 提高联系效率 | 一处编辑、预览和批量发送，保留个性化内容 |
| BG-06 | 建立可信体验 | 关键事实能回到来源，失败和未知状态不被伪装为成功 |

### 5.2 第一版已确认范围

| 编号 | 业务需求 | 范围说明 |
|---|---|---|
| BR-01 | 介绍首页与工具入口 | 首页说明价值，Get Started 进入工具 |
| BR-02 | 低门槛背景输入 | 自然语言、可选简历；其他条件后补或筛选 |
| BR-03 | UW 全校公开信息探索 | 不预设少数院系，支持跨院系；不声称完整覆盖所有教授 |
| BR-04 | 可理解、可核实的推荐 | 研究说明、理由、来源链接和条件标签 |
| BR-05 | 候选比较与选择 | 列表、详情、收藏与少量候选并排比较 |
| BR-06 | 正确的下一步 | 区分邮件、表单、项目申请、暂无空缺和未知 |
| BR-07 | 两种邮件生成方式 | 快速批量草稿、可选短问题个性化、编辑预览 |
| BR-08 | 邮箱连接与批量发送 | 用户本人授权、逐封独立发送、状态记录与失败处理 |

“全校范围”表示搜索意图和来源覆盖不被人为限制在几个院系，不表示第一版拥有校方完整人员数据库。实际发现、已核实、暂未访问到的信息必须区分。

### 5.3 不纳入第一版

- 外校科研市场、研究生申请和博士招生匹配。
- 实验室入驻端、教授后台、私有招聘名额数据库。
- 以学生已掌握技能或具体岗位需求为核心的工作任务匹配。
- 强制科研试做、技能考试、申请成功率预测。
- 根据论文数量或学校声誉制作推荐排行榜。
- 自动投递申请表、自动面试、自动跟进催信、完整收件箱管理。
- 住房、课程管理等与当前流程无关的功能。

## 6. 成功定义与验证方式

以下为第一轮验证建议，不是已获得的用户数据或已证明的效果。

### 6.1 建议的首轮验证

邀请 5 名符合主要用户画像的学生，使用相同公开资料范围，比较本产品、手动网页检索和通用联网 AI。顺序轮换，避免后完成的方案占有前一次学习带来的优势。相同用户背景、方向和任务应保持一致，不为产品隐藏竞争基线可访问的资料。

| 指标 | 定义与采集方式 | 初始判断标准（建议） |
|---|---|---|
| 独立完成探索 | 无主持人代操作，从首页走到候选选择和下一步 | 5 人中至少 4 人完成 |
| 理解与比较 | 能用自己的话说明两个候选的研究问题及区别；核对是否与来源相符 | 5 人中至少 4 人完成，保留具体误解记录 |
| 形成行动计划 | 能说出联系谁、为什么、通过什么渠道 | 5 人中至少 4 人给出完整回答 |
| 使用成本 | 完成同一选择任务的时间、反复查找与复制次数 | 与基线比较，不在测试前宣称提升比例 |
| 信息可信度 | 抽查展示的身份、联系信息、条件和研究描述 | 重要结论有直接依据；发现错误后修正并复查同类规则 |
| 邮件真实性 | 检查草稿是否包含学生没有确认过的经历、读论文或技能表述 | 验收样本不出现虚构经历 |
| 发送可靠性 | 在团队控制且获授权的测试邮箱验证逐封发送与异常状态 | 无误收件人、无意外重复发送、不虚报送达 |

回复率和进入实验室的比例可以在后续自愿反馈中观察，不能作为黑客松期间已证实的效果。当前没有学生总体规模、获客成本或付费意愿证据。

### 6.2 完成标准

完整第一版必须包含 BR-01 至 BR-08。若学校邮箱授权受限，探索和邮件草稿模块可以作为部分成果展示，但不能将“复制邮件”或“模拟发送”宣称为已完成真实批量发送。

## 7. 可行性与关键依赖

### 7.1 内容与推荐

通过校内目录、院系页面、实验室主页、经身份核对的教授个人网站及公开研究资料建立候选。建议复用已核实信息，并按需要重新核查动态条件。数据获取方式和技术实现由后续技术方案决定。

网页缺失、陈旧、身份同名和跨院系关联是质量风险。推荐的前提是研究相关且身份、归属有依据；不要求每位教授都公布可用名额。

### 7.2 邮箱发送

UW 官方文档说明学校邮箱属于 Microsoft 365。Microsoft Graph 提供用户授权后的邮件发送能力，但应用是否能被 UW 账户授权，取决于实际的组织政策和权限配置。[S4–S6]

因此，“填写自己的邮箱地址”不足以从该邮箱发送。产品需要正常登录授权流程。**批量发送属于已确认的第一版需求，UW 授权可行性属于尚未验证的依赖。** 开发启动后应优先验证，不应等到展示前才发现。

学校关于 Outlook 加载项的说明还涉及管理员批准限制，但加载项政策不能直接证明独立网页应用会被允许或拒绝。[S7] 本文不将该政策扩大解释为所有应用均不可接入。

### 7.3 成本与资源

主要成本类别为搜索和页面获取、模型调用、资料更新、基础托管和团队核查时间。尚未选择服务商和规模，因此不提供虚构预算或运行成本。

需要承担的职责包括产品与内容、交互设计、搜索与推荐、工具界面与状态管理、邮箱接入和质量验证；多人可兼任，具体分工和日程待团队确定。

第一版不预设订阅、收费、广告或学校采购模式。先验证学生是否愿意使用、能否更好地理解研究及完成下一步。

## 8. 主要风险与应对

| 风险 | 业务影响 | 处理原则 |
|---|---|---|
| 只有列表和邮件功能，用户更愿意用现成 AI | 增量价值不足 | 优先验证理解与比较体验，而非增加无关功能 |
| 全校资料不完整 | 漏掉候选、产生“只有这些教授”的错觉 | 显示检索范围与限制，允许明确搜索教授，按需扩展 |
| 模型把未知条件写成事实 | 导致错误选择和联系 | 条件三态、逐项来源、冲突说明、必要时不下结论 |
| 教授信息与当前身份不一致 | 联系错误对象 | 校内归属和联系信息核查、更新记录 |
| 邮箱授权无法通过 | 不能完成承诺的批量发送 | 早期实测；保留草稿；如受阻明确报告能力未完成 |
| 批量内容缺乏个人理解 | 失去项目初衷 | 联系前保留研究说明；支持对重点对象加入真实回答 |
| 发送超时或部分失败 | 重复发信或误认为已发送 | 逐封状态、区分失败与未知、只重试确定失败项 |
| 初始范围过大 | 黑客松无法完成完整流程 | 保留全校搜索目标，缩减非核心附加功能；不偷换为仅展示少量假数据 |

## 10. 已确认决策与剩余事项

### 10.1 已确认，不重复讨论

- UW–Madison 本校本科生、第一段科研经历为核心画像。
- 面向全校公开信息，允许跨院系探索，不仅覆盖少数固定院系。
- 模糊／明确／多兴趣输入使用不同的结果组织方式。
- 简历、技能、时间、薪酬与学分偏好不是开始搜索的强制条件。
- 通俗解释、公开来源、标签、教授详情和比较是主要体验。
- 支持快速批量生成、短问题个性化和真实批量发送。
- 介绍首页先于工具，主按钮为 Get Started。
- 当前先出文档，不开始产品代码开发。

### 10.2 待确定或待验证

| 项目 | 当前处理 |
